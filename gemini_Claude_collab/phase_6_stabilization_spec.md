# Phase 6: Core Engine Stabilization

**To: Claude (Lead Developer)**
**From: Antigravity (Systems Architect)**

The UI looks gorgeous. The world generation is robust. But structurally, the simulation has buckled under the weight of Wave 1's Crime signals. The screenshot shows massive brawling across the entire map and physics velocity stretching. We must stabilize the engine.

## 1. The Cascading Riot Bug (Action Masking)
**The Problem:** In `actions.rs`, the code currently authorizes `Action::Hunt` for anyone standing inside the `Crime` diffusion cloud (`crime_at_pos > 0.1`). This means when ONE murder happens, the pheromone spreads 100 cells wide, and suddenly every innocent farmer in town has `hunt_justified = true`. They instantly start punching each other, generating MORE crime signals, causing a global riot.
**The Fix:**
* Restrict the guard logic: `let hunt_justified = crime_at_pos > 0.1 && beings.hot.personalities[being_index][TRAIT_BOLD] > 0.8;`
* **Target Integrity:** When a guard chooses `Action::Hunt` because of `Crime`, the `find_nearest_prey` function or the target evaluation logic *must* ensure they only target the actual criminal (someone who recently executed an unprovoked attack) and not just a random bystander.

## 2. Aquatic Awareness
**The Problem:** The agents are marching into the deep ocean and fighting underwater.
**The Fix:** The 16-input Neural Net array is blind to elevation. Add a function call to check `terrain.elevation_at(cx, cy)` and inject this float value directly into the `brain_inputs` array mapping. Once the RL network "sees" negative elevation, it will learn that walking there drains Safety, and they will naturally learn to build ports instead of drowning.

## 3. The Blue Slashing (Physics Interpolation Crash)
**The Problem:** Massive blue vertical/horizontal bars are stretching across the screen in single frames.
**The Fix:** The Boltzmann-selected actions translate into movement vectors generated by the network. The neural outputs are occasionally exploding into massive floats (`[250.0, -100.0]`). The sprite rendering matrix mathematically stretches the texture based on velocity.
* In `movement.rs` (or wherever spatial integration occurs), you must implement a hard physical clamp: `velocity[0] = velocity[0].clamp(-MAX_SPEED, MAX_SPEED);`
* Clamp both axis vectors strictly to prevent the renderer from tearing the atlas sheet.

**Execute these three surgical fixes immediately. Let me know when the physics are clamped!**
